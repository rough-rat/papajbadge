Badge description

This device is split into 2 parts - the idea was to make both parts independent and reusable (#eko) It is based on CH583 BLE-capable RISC-V module. This rather obscure MCU has been choosen due to it's price, low-power capabilities, existing rust support and bluetooth capabilities. Also, the new CH572 costs ~$0.40, and I want to try this one next.

According to rough calculations, it should work ~40 days on CR2032 battery, mostly staying in sleep mode, and waking up just to play barka each day, everyday. The badges wake up each second, to check if the time has come, and to check whether any of the buttons has been pressed. Because of that, buttons must be pressed for up to 1s to work.

The upper button is "boot" button, and normally it is needed to set the MCU into bootloader mode, when programming via USB interface (the default one). In our case, it simply lights the LEDs for 5 seconds, and goes back to sleeping again.

The lower one is the "reset" button, but it actually kinda doesn't reset the board at all, and I did not have time to examine why yet. The sleep loop checks if it was working, and if pressed, it simply reboots the firmware. It then plays the intro tune, and enters BLE pairing mode for 15 seconds or so.

Use this website to pair with the badge and set it's internal time. It should keep the time across reboots, as long as the CR2032 is not removed. It will not play barka untill the time is set.

Setting the time will cause the badge to immediatelly reboot and enter pairing mode again. This is "normal" behaviour as changing RTC time was crashing the firmware no matter what I tried. I did not write the proper "disconnect" routine, so the browser will not notice the device disapearing until timeout occurs.

Please note, the device is just for our internal MCU evaluation/learning purposes. For more info, visit github.com/rough-rat/papajbadge-rs
